# Безпека

## 1. Як повідомити про вразливість

Приватно, через GitHub: вкладка **Security → Report a vulnerability** у
репозиторії `SERGIUSH-UA/gpurunner`. Публічний issue для цього не годиться.
Відповідь — протягом тижня. Підтримується остання мінорна версія.

## 2. Що gpurunner робить із вашими секретами

- Обліковки бекендів читаються зі змінних оточення, з теки конфігурації
  (`GPURUNNER_CONFIG_DIR`) або зі стандартних місць офіційних CLI. У репозиторій,
  у маніфест прогонів і в логи вони не пишуться.
- На орендований бокс Vast їдуть: код раннера, параметри job'а й тимчасові
  підписані посилання на дані. Ключі R2 і ключ API Vast туди не потрапляють;
  самознищення боксу користується ключем, який контейнеру видає сам Vast.
- Параметри `-p` підставляються в код раннера через `repr`, а не склеюванням
  рядків.
- Локальний дашборд (`gpurunner dash`) слухає лише `127.0.0.1`.

## 3. Свідомі рішення, про які варто знати

- **`post_fetch` у `plan.json` виконує команди.** Після повного забору наглядач
  запускає перелічені в плані команди на вашій машині. План — довірений вхід,
  як shell-скрипт: чужий `plan.json` не запускайте.
- **Бекенд Beam виконує отриманий із боку бекенда код раннера** (`exec`), бо так
  влаштована доставка коду в його контейнер. Код цей — той самий, що його
  відрендерив ваш gpurunner.
- **Орендований бокс — чужа машина.** Усе, що на нього поклали, власник хоста
  теоретично може прочитати. Не відправляйте туди те, чого не можна показувати.
- **Токен R2 обмежуйте одним бакетом:** gpurunner пише лише в `R2_BUCKET`, але
  токен на весь акаунт відкриває й решту.

## 4. Гроші

Vast тарифікує погодинно, доки інстанс не знищено. `gpurunner burn` показує, що
горить зараз, прямим запитом до Vast; `gpurunner cancel --all-running` гасить
усе. Наглядач гасить оренду сам, але після аварійного завершення процесу
перевірте `burn` руками.
