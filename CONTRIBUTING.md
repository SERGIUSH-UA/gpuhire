# Як вносити зміни

## 1. Оточення

```
git clone https://github.com/SERGIUSH-UA/gpurunner && cd gpurunner
uv sync --extra all          # dev-інструменти приходять групою `dev` самі
uv run pre-commit install    # ворота приватних даних, gitleaks, ruff
```

🔴 `uv sync --extra X` знімає extras, яких не названо. Якщо працюєте з кількома
бекендами, називайте всі одразу або беріть `--extra all`.

## 2. Перевірки

```
uv run pytest                 # без мережі й без обліковок
uv run ruff check .
uv run mypy src
python tools/scan_private.py  # 0 знахідок
```

Те саме ганяє CI на Linux (Python 3.11–3.13) і Windows (3.12): у коді є гілки
лише для Windows (`schtasks`, перевірка живості процесу).

## 3. Що важливо знати про код

- **Раннери в `_embedded/`** їдуть на бекенд текстом і виконуються на ЧУЖОМУ
  інтерпретаторі (Kaggle, Colab, образ на Vast). Не «осучаснюйте» їх під наш
  Python і не імпортуйте з них пакет `gpurunner`. Зібраний код перевіряє
  `tests/test_render_all_jobs.py`.
- **Новий job** — клас у `jobs/`, запис в обох переліках `jobs/__init__.py` і
  мінімальні параметри в `tests/test_render_all_jobs.py`, якщо йому мало
  `dataset`.
- **Те, що читають інші програми**, описано в `docs/contract.md`, а форму
  `--json` тримає `tests/test_cli_json_contract.py`. Прибрати поле чи прапорець
  звідти можна лише зі зміною мінорної версії та `schema`.
- **Гроші.** Усе, що орендує залізо, мусить мати стелю витрат і шлях зупинки.
  Тест, який ходить у платний бекенд, у репозиторій не приймається.
- **Мова.** Ідентифікатори — ASCII; коментарі, довідка CLI й повідомлення —
  українською. Коментар пояснює ПРИЧИНУ рішення (дата інциденту, замір), а не
  переказує код.

## 4. Приватні дані

Інструмент виріс поруч із приватним дослідженням, тому перед комітом стоять
ворота `tools/scan_private.py`: шляхи чужої машини, особиста пошта, назви
приватних репозиторіїв, токени. Виняток — лише точковий (правило × файл) у
`ALLOW` із поясненням, чому це не приватне.

Реєстр боксів (`boxes.jsonl`) у репозиторій не кладеться ніколи — це дані
користувача.

## 5. Реліз

В одному коміті перед тегом:

1. `CHANGELOG.md` — розділ `## [X.Y.Z] — РРРР-ММ-ДД` замість `[Unreleased]`;
2. `src/gpurunner/__init__.py` — `__version__ = "X.Y.Z"` (єдине джерело версії).

Перевірити текст сторінки релізу: `python tools/release_notes.py X.Y.Z`.

Далі `git tag -a vX.Y.Z -m "vX.Y.Z" && git push origin main vX.Y.Z`. Тег запускає
`release.yml`: ворота приватних даних → ruff, mypy, pytest → журнал є → колесо,
версія якого дорівнює тегу → смоук у чистому оточенні → PyPI (Trusted
Publishing) → GitHub Release.

🔴 Колесо на PyPI не видаляється й номер не перевикористовується. Тег ставиться
лише на зелений `main`.
